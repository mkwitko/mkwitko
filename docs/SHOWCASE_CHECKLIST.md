# GitHub Portfolio — Showcase Checklist

A short operational checklist for turning public source code into recruiter-friendly, verifiable engineering evidence.

## Recommended pinned repositories (in order)

1. [udv-shop](https://github.com/mkwitko/udv-shop) — React/TanStack Start, frontend product UX.
2. [udv-shop-api](https://github.com/mkwitko/udv-shop-api) — Fastify/Prisma backend architecture.
3. [finance-app](https://github.com/mkwitko/finance-app) — native mobile engineering (Expo).
4. [lunajoy-front](https://github.com/mkwitko/lunajoy-front) — data-rich, real-time React frontend.

Leave any additional slots empty until a fifth project has real documentation and evidence. GitHub allows six pins; quantity is not a quality signal.

## Capture genuine screenshots

Screenshots should be generated by running the actual applications, using seeded or demo data. Do not produce synthetic mockups and label them as product screenshots.

For each project, aim for:

- One informative desktop/mobile overview showing the UI.
- One detailed workflow (e.g. product management, transaction import, data visualization).
- A one-sentence caption: what is visible, why it matters, and what was implemented.
- Anonymization of credentials, emails, addresses, payment details, tokens, personally identifying information and internal URLs.
- A verified demo link **only if** public access is intentionally allowed and safe.

Add files under each repository's \`docs/media/\` and link from the project README. Prefer compressed PNG/WebP for screenshots; add descriptive alternative text.

## Architecture credibility checklist

- [x] Project stack and code references documented.
- [x] Core responsibilities illustrated using source-grounded diagrams.
- [ ] CI checks checked against current runs (no hypothetical green badge).
- [ ] Real before/after metrics captured and methodology documented.
- [ ] README links reviewed in a signed-out browser.
- [ ] Production/demo status explicitly stated.
- [ ] Permissions checked for customer/employer-owned code and brand assets.
- [ ] Open source licensing/attribution reviewed, especially starter template licenses.
- [ ] Secret scanning and dependency review run; any compromised credentials rotated.
- [ ] Repository About description, topics and homepage URLs finalized.

## Profile enhancements deliberately avoided

- **Public stats cards:** third-party endpoints have reported rate-limit and downtime problems. Native GitHub contribution graphs remain visible without an embedded dependency.
- **Daily 'snake' animation:** [Platane/snk](https://github.com/Platane/snk) is an option, but consumes visual space and a scheduled workflow without demonstrating software quality. Add only if the intended audience prefers a playful profile.
- **Unverified badges:** do not embed build, coverage, production or user-count badges without real backing data.

## GitHub settings — actions requiring the profile owner

1. Open [your profile](https://github.com/mkwitko) → **Customize your pins**. Select the four repositories above.
2. Add a concise GitHub bio, for example: \`Senior Software Engineer | React, Node.js, React Native & Applied AI | Open to remote roles\`.
3. Add a working portfolio/LinkedIn URL only after confirming the correct public account.
4. Check that the displayed contact email is intended to be public.
5. Consider enabling private contribution counts in profile settings without disclosing repository names or details.

## Follow-up documentation priorities

1. Capture screenshots and 30–60 second guided demos after running applications locally.
2. Add measurable results: response times, bundle size, test coverage, performance budgets; retain evidence/methods.
3. Improve quality gates and GitHub Actions where missing.
4. Create a sanitized *technical narrative* for private Applied AI work, with owner review before any publication.
